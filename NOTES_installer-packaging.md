# Installer packaging notes

## Scope

This change adds packaging templates only. It does not build a PyInstaller
bundle, run Inno Setup, sign an artifact, submit anything for notarization,
publish a release, or change application code.

## Files added

- `packaging/windows/WhisperDictate.iss` wraps the versioned PyInstaller
  Windows onedir payload in a non-elevated per-user Inno Setup installer.
  It exposes optional Start Menu and desktop shortcuts and uses Inno's
  uninstaller support.
- `packaging/macos/build_signed_dmg.sh` is an Apple Silicon release template
  that takes an explicit Developer ID identity and a preconfigured
  `notarytool` keychain profile. It can produce a stapled `.app` zip or a
  signed/notarized DMG after all release gates pass.
- `packaging/macos/entitlements.plist` is a non-secret input for the macOS
  signature.
- `packaging/README.md` documents the shared payload, portable artifacts,
  build inputs, model policy, and signing/notarization gates.
- `tests/test_packaging.py` performs text-only checks and has no platform,
  installer, container, or network dependency.

## Important decisions

1. The Windows template defaults to
   `%LOCALAPPDATA%\Programs\Whisper Dictate`, sets
   `PrivilegesRequired=lowest`, and does not allow an administrator override.
   The application writes runtime configuration, logs, history, and its model
   cache below the per-user installation/cache locations; it is not directed
   into a Program Files tree.
2. The installer sources only the prepared
   `dist/WhisperDictate/` onedir directory. The source guard filters common
   model-cache paths and model-weight extensions. No installer step downloads
   or unpacks a model; first-run model acquisition remains the application's
   responsibility.
3. The Windows and macOS templates consume the same PyInstaller output family:
   the Windows onedir directory and the macOS `.app` generated by
   `WhisperDictate.spec`. Portable archives do not contain models either.
4. The macOS script deliberately has no default signing identity and no
   credentials. The operator must select an installed
   `Developer ID Application: ...` identity and configure a notarytool
   keychain profile outside the repository. The script verifies the signature,
   notarization, stapling, and Gatekeeper assessment before emitting an
   artifact.

## Local verification

The added tests are intentionally runnable on Windows without a build:

```text
python -m unittest discover -s tests -p "test_packaging.py"
```

No PyInstaller, Inno Setup, macOS, Docker, or network access is needed. A real
release still requires a clean payload inspection, the repository's normal
application tests, and the platform-specific signing/notarization gates
described in [`packaging/README.md`](packaging/README.md).
